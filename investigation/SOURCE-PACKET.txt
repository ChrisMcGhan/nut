1: NUT.EXE(8)
2: ==========
3: 
4: NAME
5: ----
6: 
7: nut.exe - NUT for Windows wrapper for all-in-one service
8: 
9: SYNOPSIS
10: --------
11: 
12: *nut.exe* {-h | /?}
13: 
14: *nut.exe* ['OPTIONS']
15: 
16: *nut.exe* (as a service implementation)
17: 
18: DESCRIPTION
19: -----------
20: 
21: *nut.exe* wraps NUT programs to start and stop as a Windows service.
22: 
23: Depending on linkman:nut.conf[5] setting of 'MODE', it would manage the
24: bundle of driver(s), linkman:upsd[8] data server and linkman:upsmon[8] client,
25: as well as attempt an UPS shutdown command in case of FSD handling, or for
26: mere 'netclient' systems it would run just the linkman:upsmon[8] client to
27: monitor remote UPS device(s) and initiate the OS shut down on the local
28: Windows system as applicable.
29: 
30: Beside launching or stopping a set of the NUT programs in certain cases,
31: this helper program also allows to register (or un-register) itself as a
32: Windows service. To actually manage the service from command line you can
33: execute the Windows `net` or `sc` commands, e.g.:
34: 
35: ----
36: net stop "Network UPS Tools"
37: net start "Network UPS Tools"
38: sc query "Network UPS Tools"
39: ----
40: 
41: You can also execute `nut start` to automatically register the service
42: (if not yet registered) and start it, and `nut stop` to stop the service
43: (if registered and running), and `nut status` to check on it (if registered).
44: 
45: Note that for a Windows machine to act as a NUT data server for further
46: clients, you may have to add Windows Firewall rules to allow incoming
47: connections (by default to port `3493/tcp`), e.g. using PowerShell to
48: elevate (alternately right-click a "Command Prompt" shortcut and select
49: "Run as administrator"), and execute `netsh` to actually configure the
50: needed "Advanced Firewall" rule (align the path to binary with your
51: installation):
52: 
53: ----
54: REM Elevate to administrator status then run netsh to add firewall rule.
55: REM Recommended to adapt "LocalIP" to expected listeners of this server,
56: REM and "RemoteIP" to your single or comma-separated subnet(s) in CIDR
57: REM notation, specific client IP address(es), or ranges of address(es)
58: REM (dash-separated, as IP1-IP2).
59: 
60: REM The following goes as one long command line:
61: 
62: powershell.exe -Command "Start-Process netsh.exe -ArgumentList
63:   \"advfirewall firewall add rule name=NUT-upsd-data-server
64:     dir=in action=allow localip=ANY remoteip=ANY
65:     program=%ProgramFiles%\NUT\sbin\upsd.exe
66:     localport=3493 protocol=tcp\" -Verb RunAs"
67: ----
68: 
69: Keep in mind that by default NUT linkman:upsd[8] only listens on `localhost`,
70: so you would need to add some `LISTEN` directives in linkman:upsd.conf[5] as
71: well in this case.
72:

74: -------
75:

77: run as the implementation of a registered Windows service; it would error
78: out otherwise.

82:

84: Display the help text and exit.
85:

87: Display NUT version and exit.

91: The non-trivial debug level would be passed down to launched NUT programs.
92: Primarily useful for troubleshooting with the non-service mode.

96:

123: DIAGNOSTICS
124: -----------
125: 
126: *nut.exe* should not interact with console message buffers (`stdout`, `stderr`)
127: much, except when explicitly asked to (e.g. displaying help and NUT version,
128: running with verbose debug mode) or when exiting after an attempted service
129: initialization while not running in a service context.
130: 
131: Most of normal logging from *nut.exe* goes to the Windows Event Log.
132: 
133: Launched NUT programs may emit messages of their own; their fate when no
134: console is attached is questionable. The service may be cheerfully "running"
135: (as long as `MODE=...` is set in `nut.conf`), but specific daemons under it
136: might refuse to start. For example, it may be troublesome to see (without
137: perusing the Windows Event Log, Applications section) whether they are missing
138: some configuration file or entry. You may have to launch respective daemons
139: manually to check what they complain about, or use *nut.exe -N* mode,
140: all with raised NUT debug verbosity settings.
